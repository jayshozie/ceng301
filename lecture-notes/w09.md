# Priority Queue ADT

A `priority queue` is a collection of ordered elements that provides fast
access to the minimum (or maximum) element. You can say that a priority queue is
a `most-important-out-first`.

## Default Member Functions

- `add()`: Adds in order
- `peek()`: Returns **minimum** or **highest priority** value
- `remove()`: remove/returns **minimum** or **highest priority** value

## Types

### Min Priority Queue ADT

- **state**: set of comparable values, ordered based on priority
- **behavior**:
    - `removeMin()`: returns the element with the ***smallest*** priority, then
    removes it from the collection
    - `peekMin()`: return the element with the ***smallest*** priority, but
    **don't** remove it from the collection.
    - `add(value)`: add a new element to the collection

### Max Priority Queue ADT

- **state**: set of comparable values, ordered based on priority
- **behavior**:
    - `removeMin()`: returns the element with the ***largest*** priority, then
    removes it from the collection
    - `peekMin()`: return the element with the ***largest*** priority, but
    **don't** remove it from the collection.
    - `add(value)`: add a new element to the collection

## Heap

The `heap` is the classic method used to implement priority queues. It is
different in from the term *heap* used in dynamic memory allocation.

### Properties

1. Structure Property

> [!IMPORTANT]
> A heap is a ***complete binary tree***.

<details>
    <summary> Types of Binary Trees </summary>

- **Full Binary Tree:** A binary tree T is *full* if each node is either a leaf,
or possesses exactly two child nodes.
- **Complete Binary Tree:** A binary tree T with `n` levels is *complete* if all
*levels* except possibly the last are completely full, and the last level has
all its nodes to the left side.
</details>

A **complete** binary tree is a tree where every level is full except possibly
the lowest level, which must be filled from left to right.

2. Ordering Property

> [!IMPORTANT]
> In a heap (a.k.a. **min heap**), every node is *less than or equal to both of
> its children*.

The above property is what makes the heap, an implementation of priority queue.
It ensures that the node with the min priority is at the root, and everything
less important are down under.

> [!WARNING]
> This property is exactly the opposite in a max heap. In a **max heap** every
> node is *greater than or equal to both of its children*.

<u>The default is **min heap.**</u>

### Heap Height and Runtime

The height of a complete tree is always $\log_{2}{n}$, because of this property,
if we implement a priority queue using a heap, we can provide the following
runtime guarantees:
- `add`       : $`O(\log{n})`$
- `peekMin`   : $`O(1)`$
- `removeMin` : $`O(\log{n})`$

### `add` Operation

When an element is added to a heap, where should it go?

- When an element is added to a heap, it should be initially placed as the
*rightmost leaf* (to maintain the completeness property), but that breaks the
ordering property, what do we do? We bubble up.

- **`bubble (percolate) up`:** To restore heap ordering, the newly element is
shifted (*bubbled*) up the tree until it reaches its proper place.

### `peekMin` Operation

- A `peekMin` on a min-heap is trivial to perform, because of the heap's
properties, minimum element is always the root. ($`O(1)`$) 

- `peekMax` on a max-heap would be $`O(1)`$ as well, (returns max, not min).

### `removeMin` Operation

- When an element is removed from a heap, what should we do? The root is the
node to remove, so how do we alter the tree, so that it doesn't get cut in half?
It should initially be replaced by the *rightmost leaf* (to maintain
completeness), but that breaks the heap ordering property. So, this time, we
bubble down.

- **`bubble (percolate) down`:** To restore heap ordering, the new improper root
is shifted (*bubbled*) down the tree until it reaches its proper place.
